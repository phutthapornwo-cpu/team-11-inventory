> หมายเหตุ: ภาพเป็นแนวทางการออกแบบเพื่อใช้ประกอบเอกสารโครงการ ไม่ใช่หน้าจอที่เชื่อมต่อกับระบบจริง และข้อมูลตัวเลขในภาพเป็นข้อมูลตัวอย่างสำหรับการออกแบบเท่านั้น

## ไฟล์ภาพ

## เป้าหมายการออกแบบ
- ช่วยให้พนักงานค้นหาและตรวจสอบรายการสินค้าได้ง่าย
- แสดงสถานะสต็อกต่ำอย่างเด่นชัด
- แสดงมูลค่าสต็อกแยกตามหมวดหมู่และมูลค่ารวม
- แยกส่วนแจ้งเตือนออกจาก Business Logic ของการจัดการสต็อก
- รองรับการใช้งานบนหน้าจอขนาดต่าง ๆ

## หน้าจอที่ออกแบบ

### 1. หน้าหลัก / Dashboard
แสดงสรุปจำนวนรายการสินค้า มูลค่าสต็อกรวม จำนวนการแจ้งเตือนสต็อกต่ำ และภาพรวมมูลค่าตามหมวดหมู่ พร้อมรายการสินค้าที่ต้องติดตาม

### 2. หน้ารายการสินค้า
แสดงรหัสสินค้า ชื่อสินค้า หมวดหมู่ จำนวนคงเหลือ และสถานะสต็อก มีช่องค้นหาและปุ่มเพิ่มสินค้า ทั้งนี้ชื่อฟิลด์และการกระทำต้องปรับให้ตรงกับฟังก์ชันที่มีจริงในระบบ

### 3. รายงานมูลค่าสต็อก
สรุปมูลค่าตามหมวดหมู่ โดยคำนวณจาก `จำนวนคงเหลือ × ราคาต่อหน่วย` และแสดงมูลค่ารวมทุกหมวดหมู่

### 4. แจ้งเตือนสต็อกต่ำ
แสดงสินค้าที่มีจำนวนคงเหลือน้อยกว่าหรือเท่ากับ Threshold พร้อมจำนวนคงเหลือและ Threshold ที่กำหนด

## กติกาจาก Spec
- แจ้งเตือนเมื่อ `quantity <= threshold`
- ปฏิเสธรายการจ่ายเมื่อจำนวนที่จ่ายมากกว่าสต็อกคงเหลือ
- รายการรับ/จ่ายที่ไม่สำเร็จต้องไม่เปลี่ยนจำนวนสต็อก
- รายงานมูลค่ารวมคำนวณจากผลรวมมูลค่าสินค้าในทุกหมวดหมู่
- ในขอบเขตปัจจุบัน การส่ง Email/SMS จริงยังไม่รองรับ สามารถแสดงการแจ้งเตือนผ่าน CLI หรือใช้ Mock สำหรับทดสอบได้

## แนวทางสีและองค์ประกอบ
- **Primary Blue:** ปุ่มหลักและรายการที่เลือก
- **Navy:** Sidebar และองค์ประกอบนำทาง
- **Success Green:** สถานะปกติ
- **Warning Orange:** สต็อกต่ำหรือรายการที่ต้องติดตาม
- **Danger Red:** ข้อผิดพลาดหรือสต็อกต่ำมาก
- **Neutral White/Gray:** พื้นหลัง ตาราง และการ์ดข้อมูล

## Accessibility Checklist
ก่อนนำไปใช้งานจริง ควรตรวจรายการต่อไปนี้และบันทึกผลที่ตรวจได้จริง

- [ ] ข้อความและพื้นหลังมีอัตราส่วนความต่างสีที่อ่านได้
- [ ] ไม่ใช้สีเพียงอย่างเดียวในการบอกสถานะ ต้องมีข้อความหรือไอคอนประกอบ
- [ ] ปุ่ม ลิงก์ ช่องค้นหา และตัวควบคุมสามารถใช้งานด้วยคีย์บอร์ดได้
- [ ] ช่องกรอกข้อมูลมี Label ที่ชัดเจน
- [ ] ตารางมีหัวคอลัมน์ที่เข้าใจได้ และลำดับโฟกัสเหมาะสม
- [ ] ทดสอบการแสดงผลบนหน้าจอแคบและการซูม
- [ ] บันทึกเครื่องมือที่ใช้ตรวจ ผลที่พบ และการแก้ไข

> อย่าทำเครื่องหมายว่า Accessibility ผ่านแล้วจนกว่าจะตรวจหน้าจอหรือ Prototype จริง

## สิ่งที่ต้องปรับก่อนส่งงาน
1. ตรวจให้ชื่อเมนู ฟิลด์ และปุ่มตรงกับฟังก์ชันที่ระบบทำได้จริง
2. ใช้ข้อมูลตัวอย่างที่ระบุชัดว่าเป็นข้อมูลสมมติ
3. แนบภาพหน้าจอจาก Prototype หรือระบบที่ทำงานจริง หากมี
4. บันทึกผล Accessibility จากการตรวจจริง
5. หากระบบที่ส่งจริงเป็น CLI เท่านั้น ให้ระบุภาพ Dashboard นี้เป็นแนวคิดการออกแบบเพิ่มเติม ไม่ใช่หน้าจอที่มีอยู่ในโปรแกรมปัจจุบัน
